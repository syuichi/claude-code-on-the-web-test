Claude Code on the web 体験まとめ

農家訪問記録アプリを作りながら on the web を試した記録

やったこと概要

Claude Code on the web（claude.ai/code）を使って、農業従事者向けの訪問記録アプリをゼロから作成。あわせて GitHub Pages で公開するまでの流れを体験した。

ステップごとの記録

1セッションスタートフックの設定

on the web でセッションを開始したとき自動で実行されるスクリプトを作成。依存関係のインストールなどをここに書いておくことで、毎セッション環境が整った状態で始められる。

  • .claude/hooks/session-start.sh を作成
  • .claude/settings.json に SessionStart フックとして登録
  • 今回のリポジトリは空だったため、フックの中身は最小限（リモート環境チェックのみ）
SessionStart hook .claude/settings.json
2訪問記録アプリの作成

HTML 1ファイル構成でシンプルに実装。バックエンド不要。

  • 生産者名・農場名・訪問日時・作物・メモ・写真を記録
  • データは localStorage に保存（ページを閉じても残る）
  • 記録の一覧表示・削除に対応
  • スマホ・PC 両対応のレスポンシブデザイン
HTML/CSS/JS localStorage レスポンシブ
3プレビューの確認（ハマりポイント）

コンテナ内で python3 -m http.server 3000 を起動したが、on the web の UI にポートプレビュー機能が見当たらなかった。

現時点では Claude Code on the web にポートのプレビューURL機能はない模様。ドキュメントにも記載なし。

→ 代替策として GitHub Pages での公開に切り替えた。

4GitHub Pages での公開

index.html を main ブランチにプッシュし、GitHub Pages を有効化した。

  • GitHub MCP ツールで main ブランチへ直接プッシュ
  • GitHub Pages の有効化は API トークンの制限により手動で実施
    （Settings → Pages → Branch: main / root → Save）

公開URL: https://syuichi.github.io/claude-code-on-the-web-test/

GitHub Pages main ブランチ

学んだこと・気づき

  • セッション = コンテナ起動：on the web を開くたびにクラウドコンテナが起動し、リポジトリがクローンされる
  • ファイルはコンテナ内に存在：/home/user/ 以下はローカルPCではなくコンテナのパス。git push したものだけが残る
  • localStorage のスコープ：ブラウザに保存されるためデータは端末ごとに独立。永続化・共有が必要な場合は Supabase 等の外部サービスが必要
  • ポートプレビューは現状未対応：静的サイトの確認には GitHub Pages が現実的
  • GitHub MCP ツール：Claude から直接 GitHub へのプッシュ・PR作成などが可能
